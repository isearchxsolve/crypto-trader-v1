This is the **"never-green" problem**. In memecoins, a token that does not go green in the first 18 seconds is almost certainly a rug, a honeypot, or a failed launch. The engine was letting these trades bleed to -20% via the cost-widened stop loss.

**Fix #3: Hard Stop Tightened**

## 6. The Safety Architecture: How the Engine Survives Its Own Mistakes

### 6.1 Dual-Signal Watchdog (`failsafe.cjs`)

The Moonshot Architecture runs an **independent supervisor process** that monitors the trading engine via two signals:

- **Heartbeat**: The engine writes a timestamp every 5 seconds
- **HTTP Health**: The engine serves `/api/health` on its configured port

**The supervisor only escalates to PANIC when BOTH signals fail simultaneously.** This prevents false liquidations from transient network issues. The escalation cascade is:

1. **HALT** — Write `.HALT` file; engine refuses new buys
2. **KILL** — Stop the engine process via PM2 (never `pkill node` — that would kill the supervisor itself)
3. **LIQUIDATE** — Run the standalone liquidator to emergency-sell ALL memecoin positions to SOL
4. **FLAG** — Write incident JSON to `incidents/` directory
5. **AUTO-FIX** — If `AUTO_FIX=true`, launch the automated repair pipeline

### 6.2 Circuit Breakers

Three independent circuit breakers protect the wallet from catastrophic drawdown:

| Breaker | Trigger | Action |
|---------|---------|--------|
| **BTC Crash** | Bitcoin down >5% in 24h | Halt trading + swap SOL to USDC (flight to safety) |
| **Daily Loss Limit** | Net daily PnL ≥ 20% (30% for micro wallets) | Halt trading + flight to safety |
| **Max Drawdown** | Portfolio drawdown ≥ 45% from peak | Halt trading + manual intervention required |

### 6.3 The Liquidator (`dist/liquidator.cjs`)

A standalone emergency script that:
- Reads the wallet private key + RPC directly from environment
- Sells ALL token positions to SOL via Jupiter — **independent of the engine**
- Runs even if the engine is completely dead
